# Hotel operational projection alignment

The Admin Hotel slice consumes redacted Hotel projections and submits care, check-in, and checkout through the intended callables. Its reservation presentation, however, renders the first pet while independently selecting the first projected stay ID; Infra sorts those IDs, so they are not a stable pair. Four list-read failure paths omit the branch freshness check, and a dossier request can apply after the operator has selected another stay in the same branch. Watch for: **confirmed** pet/stay mismatches can block or mis-target check-in; **likely** stale failures and dossier responses can replace current operational context.

**Verdict**: NEEDS_CHANGES

Scoped static validation passed: `swiftc -frontend -parse` completed for all three Swift files, and `git diff --check main -- <scoped Swift files>` returned cleanly. No `xcodebuild`, simulator, or device deployment was run for this review-only task.

## High-level view

Hotel commands stay server-owned: care and dossier data come from `hotelReadOperations`, generic task transitions use `hotelCareCommand`, and the canonical callable enforces the action permission and target-stay branch scope. The examined medication, belongings, emergency-contact, and conditional checkout gates match those projection and callable contracts.

The reservation card has no stable pet-to-stay relation (**confirmed**). It renders `pets.first` but obtains `stayIds.first`; the parent rollup sorts `stayIds` independently, so a valid multi-pet arrival can be blocked and the ViewModel still holds an uncorrelated command target.

Successful list reads use generation plus branch freshness, but failure paths only compare the generation (**likely**). Dossier loading similarly does not verify that its stay is still selected before replacing `selectedStayDetail` (**likely**), leaving same-branch navigation vulnerable to late results.

## Sorted reservation `stayIds` are not a pet/stay identity map

`AdminHotelReservation.fromDictionary` renders `pets.first`, while `AdminPetsHotelCheckInSheet.authoritativeCheckInStay` and `AdminPetsHotelViewModel.executeCheckIn` choose `reservation.stayIds.first`. Infra’s `syncReservationFromStays` derives `stayIds` with `.sort()`, while the reservation’s `pets` array retains its own order; no positional correspondence exists.

This is a **confirmed** defect. The sheet compares the selected operational stay’s pet ID and disables a mismatched pair, so valid multi-pet arrivals can be blocked. `executeCheckIn` independently submits the first ID, bypassing that comparison for any future caller. Resolve the stay from the authoritative operational-stays projection using both `reservationId` and `petId`, then pass that resolved ID through the command; represent additional stays explicitly rather than relying on array position.

## Old-branch failures can mutate the current Hotel workspace

Successful `hotelReadOperations` results require both the captured `loadGeneration` and `currentBranchId` to match. The catches for operational stays, care operations, reservation operations, and command-center reads only require the generation. This is a **likely** stale-state defect: the active branch can change before its RunLoop-delivered observer starts a new generation, allowing an old failure to clear data or publish an error under the new branch.

Apply the same generation-and-branch guard to every catch before changing state. The accommodation listener and dossier error path already use that pattern.

## A late dossier can retake detail presentation

`AdminPetsHotelStayDetailSheet` starts `loadStayDossier(stayId:)` in a view task. `loadStayDossier` rejects only a changed generation or branch, then assigns `selectedStayDetail` unconditionally. This is a **likely** stale-selection defect: after closing stay A and opening stay B in the same branch, a late A response can restore A’s binding and reopen or replace the B context.

Attach a per-dossier request identity, or require that `selectedStayDetail?.id == stayId` immediately before applying the result. Treat cancellation as non-authoritative before writing the selection.

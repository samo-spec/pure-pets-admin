# Hotel dossier refresh can restore stale, partial stay state

The requested medication-readiness and nested-counter regressions are resolved: check-in now derives its acknowledgement from the matched operational stay’s `checkInReadiness` and disables submission when that stay is unavailable, while `stay.counters` is normalized before checkout gates consume it. The original five alignment contracts also retain their intended behavior: genuine `stayIds`, canonical belongings quantity, omission of incomplete emergency contacts, callable/branch-scoped care access, and conditional acknowledgements. Two defects remain in the dossier-refresh path: it replaces a richer operational stay with a deliberately partial summary, and it applies an earlier branch’s result without the generation guard used by the primary loader. Watch for: **confirmed** a dossier open can blank identity/contact/billing state and discard readiness metadata; **confirmed** a late success or error can repopulate the newly selected branch with stale context.  
**Verdict**: NEEDS_CHANGES

## High-level view

The check-in path now binds the UI to a real, reservation- and pet-matched stay from the operational projection. That resolves the prior medication finding without reading unavailable reservation declarations, and the server continues to enforce the same requirement independently.

The first remaining issue is **confirmed**: the summary is intentionally a narrow care projection, but its parsed model replaces the full operational-stay record that the detail screen renders. The counter fix works, yet fields absent from the summary collapse to defaults.

The second remaining issue is **confirmed**: dossier loads are not invalidated when the active branch changes. The main loader clears state and increments its generation, but an in-flight detail request still writes success or failure afterward.

## The summary replaces data it never returns

The issue is **confirmed** in `AdminPetsHotelViewModel.loadStayDossier` (`AdminPetsHotelViewModel.swift:587-628`): it builds a new `AdminHotelStay` only from `summary["stay"]`, then assigns that value to both `selectedStayDetail` and `stays[idx]`. The canonical `stay_operational_summary` deliberately returns identifiers, status, accommodation data, and nested counters; it excludes `customerSnapshot`, pet breed/species, the billing ledger, and `checkInReadiness` (`Pure Pets Infra/functions/hotel/careReadModels.js:1087-1194`).

`AdminHotelStay.fromDictionary` defaults those omitted properties, while the detail sheet renders breed/species, customer name/phone, and the billing card from the replacement model. Opening a dossier can therefore blank visible identity/contact information, hide permitted billing, and replace explicit readiness metadata with the parser fallback. Preserve the existing operational record and overlay only summary-authoritative fields—status, accommodation, counters, tasks, and belongings.

```
operational_stays: identity + billing + readiness + counters
        │
        ▼ merge summary-authoritative fields
stay_operational_summary: status + accommodation + counters + dossier lists
```

## The async dossier result escapes its branch

The issue is **confirmed** in `AdminPetsHotelViewModel.swift:577-632`: `loadStayDossier` captures `branchId`, awaits `fetchStayOperationalSummary`, then writes its result or error without checking `loadGeneration` or the current branch. The branch observer invokes `loadHotelOperations`, which increments `loadGeneration` and clears the detail state (`AdminPetsHotelViewModel.swift:92-132`), while the detail sheet independently starts the dossier task (`AdminPetsHotelStayDetailSheet.swift:16-79`).

A request begun under branch A can finish after branch B is active and restore branch-A data into the cleared detail state, or surface a branch-A failure as the current error. Capture the generation before awaiting and require both that generation and `currentBranchId == branchId` before applying either outcome.
